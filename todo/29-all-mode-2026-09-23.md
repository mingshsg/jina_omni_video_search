## What changed

- `app/api/search/route.ts`:
  - `bodySchema.modality` gained `'all'`; `'both'` is kept as a deprecated
    alias (identical old behavior, no description merge) rather than a
    breaking rename, since `docs/api-contract.md` documents `both` as a
    normative wire value and nothing in this codebase's scripts calls the
    HTTP route with `modality: "both"` (only `searchChunks()` directly,
    which is unaffected \u2014 verified via grep of `scripts/**/*.ts`).
  - New `isAllMode` / `chunkModality` split: `chunkModality` is `'both'`
    when the wire value is `'all'`, otherwise passed through unchanged. All
    existing chunk-search logic (hybrid text, parse_query, sort_by,
    RRF/knn) now reads `chunkModality` instead of `body.modality` \u2014 the
    `effectiveSort` calculation was the one place this mattered
    (previously `body.modality !== 'both'` would have miscomputed for the
    new `'all'` wire value).
  - When `isAllMode`, `searchChunks(...)` (with `modality: 'both'`,
    unchanged internal semantics) and `searchDescriptionAssets(...)` now run
    concurrently via `Promise.all`. The description call is soft-failed
    (`.catch(() => null)`) so an unavailable/erroring semantic channel
    degrades "All" mode to chunk-only results rather than a 500.
  - Response gains `description_hits` (only present when `isAllMode`):
    description matches whose `video_id` is not already present among the
    chunk hits, i.e. the "separate section, not blended score" design from
    `plan/11`. `meta.modality` echoes `"all"` (not `"both"`, which is what
    `searchChunks` internally returns); `meta.description_status` is
    `"ok"` or `"unavailable"`.
- `app/page.tsx`:
  - Local `Modality` type: `'visual' | 'audio' | 'all' | 'description'`
    (`'both'` renamed to `'all'`). Local `ModalityBadge` type is
    **unchanged** (`'visual' | 'audio' | 'both' | 'description'`) \u2014 a
    per-hit badge still says `'both'` when a chunk matched both the visual
    and audio knn windows under `'all'` mode; only the top-level mode
    selector is renamed. This distinction is called out in a code comment
    since it's easy to conflate the two types.
  - 4th modality button relabeled from `t.modalityBoth` to a new
    `t.modalityAll` key (the `modalityBoth` key is kept \u2014 still used for
    the per-hit badge label).
  - `runSearch`: when `modality === 'all'`, `data.description_hits` is
    mapped through the existing `mapDescriptionHitsToSynthetic()` helper
    (reused as-is from Description mode) and appended **after** the chunk
    hits in the `hits` array passed to `setHits`. `groupSearchHitsTopK`
    preserves input order for cross-video/variant group ranking (verified
    by reading `lib/es/group-hits.ts` \u2014 it only re-sorts by score *within*
    a same-video/variant temporal bucket, and ranks groups by the
    representative's original array index otherwise), so this ordering
    reliably keeps chunk RRF hits ahead of description-only hits without
    needing a new UI section/divider component.
  - All `modality !== 'both'` / `=== 'both'` checks touching the *mode
    selector* (`formatRrfScore`, `sortOptions`'s rrf-disabled flag,
    `onModalityChange`, `onHybridTextChange`) updated to `'all'`. The two
    `ModalityBadge`-switch occurrences of `'both'` (`badgeLabel`,
    `badgeColor`) are untouched \u2014 correct, since that type didn't change.
- `lib/i18n/ui.ts`: added `modalityAll` key, EN (`"All"`) + ZH (`"\u5168\u90e8"`).
  `modalityBoth` (`"Both"` / `"\u89c6\u89c9+\u97f3\u9891"`) kept as-is for the badge label.
- `docs/api-contract.md`: additive-only. `modality` request-field row lists
  `all` alongside `both` (marked deprecated alias) and `description`; new
  "Description mode and All mode" subsection documents both branches
  (Description mode's doc paragraph didn't exist before this pass either \u2014
  backfilled here since it was a pre-existing gap from `todo/28`, not

  documentation is untouched since that internal chunk-level contract did

- `plan/11-semantic-text-search-modes.md`: corrected in place per this

  "Deferred" section updated to record that All mode shipped, how, and that

## Design choices and why

- **No caller uses `modality: "both"` over the HTTP route today** except
  `app/page.tsx` itself (which this pass changes to send `"all"`). Verified:
  `scripts/smoke-phase8-search.ts` and `scripts/phase10-e2e.ts` both call
  `searchChunks()` directly (the internal function, whose
  `SearchModality` type is untouched \u2014 still `'visual'|'audio'|'both'`),
  not the HTTP API. Kept `both` as an accepted, unchanged-behavior alias
  anyway, since it's a documented external contract
  (`docs/api-contract.md`) and dropping it would be a needless breaking
  change for zero benefit.
- **"Separate section," not a blended re-ranked score** \u2014 chunk-level RRF
  scores (`rank_constant=60` fused rank) and asset-level `semantic_text`
  query scores are not on a comparable scale; inventing a normalization to
  merge them into one sorted list would be an undocumented, untested
  relevance heuristic. Appending deduped description-only hits after the
  chunk hits (both server-side ordering and client-side array order) is
  simple, honest about the grain difference, and needed zero new UI
  components since the existing "description" badge (warning color)
  already visually marks these hits as a different kind of match.
- **Dedup by `video_id`** happens server-side (in `route.ts`, comparing
  `descResult.hits` against `result.hits`) rather than client-side, so the
  `description_hits` field the client receives is already the "extra"
  set \u2014 the client only has to know to append it, not to dedup.
